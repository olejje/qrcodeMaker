# qrterm

**Генератор QR-кодів з нуля на Go: друкує код у терміналі (24-bit ANSI, half-block), зберігає PNG/SVG, вміє режими numeric/alphanumeric/kanji, ECI для UTF-8, логотип та інтерактивний перегляд.**

[![Go](https://img.shields.io/badge/Go-1.21%2B-00ADD8?logo=go&logoColor=white)](https://go.dev)
[![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)]()
[![Tests](https://img.shields.io/badge/tests-go%20test%20.%2F...-blue)](#перевірка)

![preview](assets/preview.png)

Жодних сторонніх пакетів — лише стандартна бібліотека Go. Реалізовано повний
енкодер ISO/IEC 18004: режими даних, Reed–Solomon у GF(256), інтерлівинг
блоків, функціональні патерни, BCH-захищену інформацію, вісім масок із вибором
за штрафними правилами.

---

## Можливості

- **Режими даних**: numeric, alphanumeric, byte (з автоматичним ECI 26 для
  UTF-8) та Kanji (повна таблиця JIS X 0208 — 6879 символів). Авто-режим обирає
  найкоротше подання.
- **Версії 1–40** (до 2953 байт для `L`), авто-вибір найменшої версії, BCH
  version information для v7+.
- Усі чотири **рівні корекції**: `L`, `M`, `Q`, `H`.
- **Reed–Solomon** із генераторним многочленом `0x11D`, інтерлівинг даних і ECC.
- **Вісім масок** із вибором за чотирма штрафними правилами (N1–N4).
- Термінал: `▀` + 24-bit ANSI або чистий ASCII (`-color=false`).
- **PNG** і **SVG** (self-contained, логотип вбудовується як data URI).
- **Логотип у центрі** PNG/SVG: автоматично примушує рівень `H`, малює білу
  рамку й масштабує зображення найближчим сусідом.
- **Інтерактивний перегляд** у raw mode: стрілки — панорама, `+`/`-` — zoom,
  `c` — кольори, `i` — інверсія, `r` — скидання, `q` — вихід.
- Детермінованість: той самий текст і налаштування дають той самий код.

## Швидкий старт

```bash
cd ~/projects/qrterm

go run . "привіт"
go run . -color=false "https://github.com/olejje/ascii-raytrace"
go run . -png out.png -svg out.svg -ec H "текст"
echo "привіт" | go run .

go run . -mode numeric "1234567890"
go run . -mode kanji "漢字テスト"
go run . -eci -mode byte "ABC"

go run . -logo logo.png -png with-logo.png "https://example.com"
go run . -view -ec H "https://example.com"
```

Потрібен Go 1.21+ (залежностей завантажувати не потрібно).

### Як передається текст

1. Аргументами — усе після прапорців об'єднується пробілами.
2. Без аргументів — читається **один рядок зі stdin** (введіть текст, натисніть Enter).
3. Якщо stdin перенаправлено (`echo ... |` чи `< file`) — читається весь потік до EOF.
4. Порожній ввід або `-h` — довідка з прикладами.

### Прапорці

| Прапорець | За замовчуванням | Що робить |
|---|---|---|
| `-ec` | `M` | корекція `L`, `M`, `Q` або `H` |
| `-v` | `auto` | версія `1`–`40` або авто |
| `-mode` | `auto` | `numeric`, `alnum`, `byte`, `kanji` |
| `-eci` | `false` | примусово додати ECI 26 (UTF-8) у byte mode |
| `-color` | `true` | 24-bit ANSI; `false` → `█`/`▀`/`▄` |
| `-invert` | `false` | поміняти темне й світле місцями |
| `-border` | `4` | quiet zone в модулях |
| `-png` | — | шлях до PNG |
| `-svg` | — | шлях до SVG |
| `-logo` | — | PNG/JPEG у центр (примушує `H`) |
| `-scale` | `8` | пікселів на модуль у PNG |
| `-view` | `false` | інтерактивний перегляд |

## Як це працює

```
текст → вибір режиму → біти → data codewords → ECC → інтерлівинг → матриця → маска → вивід
```

1. **Вибір режиму.** Для авто-режиму рахуються довжини трьох-чотирьох
   подань і береться найкоротше: numeric — 10 біт на 3 цифри, alphanumeric —
   11 біт на пару з алфавіту `0-9A-Z $%*+-./:`, byte — 8 біт на байт,
   kanji — 13 біт на ієрогліф JIS X 0208.
2. **ECI.** Для byte-режиму з не-ASCII символами додається сегмент
   `0111 + 00011010` (ECI 26 = UTF-8), щоб сканер одразу знав кодування.
3. **Корекція помилок.** Reed–Solomon у GF(256), дані й ECC чергуються
   між блоками згідно з таблицями версії/рівня (усі 40 версій).
4. **Матриця.** Finder/timing/alignment, темний модуль, BCH-формат і
   BCH-версія (v7+), дані зигзагом, вісім масок із мінімальним штрафом.
5. **Вивід.** Термінал — два модульні ряди на рядок тексту через `▀`;
   PNG — масштабовані квадрати; SVG — один `<rect>` на темний модуль.

## Структура проєкту

```
qrterm/
├── main.go              # CLI, stdin, рендер, PNG
├── output.go            # логотип, SVG
├── viewer.go            # інтерактивний перегляд
├── raw_linux.go         # raw mode + ioctl (Linux)
├── raw_other.go         # stub для інших ОС
├── qr/
│   ├── qr.go            # API: Encode(text, opts)
│   ├── modes.go         # numeric/alnum/byte/kanji, ECI, авто-вибір
│   ├── kanji.go         # таблиця JIS X 0208 (gen. from EUC-JP)
│   ├── tables.go        # таблиці версій 1–40, alignment, capacities
│   ├── bits.go          # бітовий потік, падіння, інтерлівинг
│   ├── reed_solomon.go  # GF(256), генератор, залишок
│   ├── matrix.go        # патерни, format/version, data placement
│   ├── mask.go          # 8 масок і штрафні правила
│   └── *_test.go
├── assets/preview.png
└── go.mod
```

## Перевірка

```bash
go test ./...
go vet ./...

# незалежне сканування
go run . -png /tmp/qr.png "hello world"
zbarimg -q --raw /tmp/qr.png

# логотип і SVG
go run . -logo logo.png -png /tmp/logo-qr.png -svg /tmp/logo-qr.svg "text"
zbarimg -q --raw /tmp/logo-qr.png

# еталонні матриці
qrencode -t ASCII -m 0 -l M -o - "hello world"
```

`TestAllVersionsAgainstQrencode` звіряє **всі 40 версій × 4 рівні** з
`qrencode` за розмаскованим потоком даних; `TestModesAgainstQrencode` і
`TestKanjiAgainstQrencode` роблять те саме для режимів. Маска вибирається
евристично й може відрізнятися від інших енкодерів, тому порівнюється не
матриця побітно, а дані. Тести з `zbarimg`/`qrencode`/`iconv` пропускаються,
якщо інструментів немає.
