# qrterm

**Генератор QR-кодів з нуля на Go: друкує код прямо в терміналі (24-bit ANSI, half-block) і вміє зберігати PNG.**

[![Go](https://img.shields.io/badge/Go-1.21%2B-00ADD8?logo=go&logoColor=white)](https://go.dev)
[![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)]()
[![Tests](https://img.shields.io/badge/tests-go%20test%20.%2F...-blue)](#перевірка)

![preview](assets/preview.png)

Жодних бібліотек — лише стандартна бібліотека Go. Енкодер реалізовано повністю:
бітовий потік, Reed–Solomon у GF(256), інтерлівинг блоків, функціональні патерни,
інформація про формат і версію, вісім масок із вибором найкращої за штрафними правилами.

---

## Можливості

- **Byte mode**, версії **1–10** (до 271 байта для рівня L), авто-вибір найменшої версії.
- Усі чотири **рівні корекції помилок**: `L`, `M`, `Q`, `H`.
- **Reed–Solomon** поверх GF(256) із генераторним многочленом `0x11D`.
- **Інтерлівинг** даних і ECC по блоках (для версій із кількома блоками).
- Повний набір функціональних патернів: три finder-патерни, timing, alignment,
  темний модуль, BCH-захищену інформацію про формат і версію.
- **Вісім масок** із вибором за чотирма штрафними правилами ISO/IEC 18004.
- Висновок у термінал: `▀` + 24-bit ANSI (або чистий ASCII-режим `-color=false`).
- PNG через `image/png`, інвертування кольорів (`-invert`), власний quiet zone.
- Детермінованість: той самий текст і налаштування завжди дають той самий код.

## Швидкий старт

```bash
cd ~/projects/qrterm

go run . "привіт"
go run . -color=false "https://github.com/olejje/ascii-raytrace"
go run . -png out.png -scale 10 -ec H "текст"
echo "привіт" | go run .
```

Потрібен Go 1.21+ (залежностей завантажувати не потрібно).

### Як передається текст

1. Аргументами — усе, що після прапорців, об'єднується пробілами.
2. Якщо аргументів немає — читається **один рядок зі stdin**: введіть текст і натисніть `Enter`.
3. Якщо stdin перенаправлено (`echo ... |` або `< file`) — читається весь потік до EOF.
4. Якщо вводу немає — програма друкує `/h`-подібну довідку з прикладами.

### Прапорці

| Прапорець | За замовчуванням | Що робить |
|---|---|---|
| `-ec` | `M` | рівень корекції `L`, `M`, `Q` або `H` |
| `-v` | `auto` | версія `1`–`10` або автоматичний вибір |
| `-color` | `true` | 24-bit ANSI та half-block; `false` → `█`/`▀`/`▄` |
| `-invert` | `false` | поміняти темні й світлі модулі місцями |
| `-border` | `4` | quiet zone в модулях |
| `-png` | — | шлях до файлу PNG (разом із виводом у термінал) |
| `-scale` | `8` | пікселів на модуль у PNG |

  █ ███ █ ██ ▀▄ █ ███ █  
  █ ▀▀▀ █ █▀ ▀█ █ ▀▀▀ █  
  ▀▀▀▀▀▀▀ █ █▄█ ▀▀▀▀▀▀▀  
  ▀ █▀▀█▀▄▄ █ █ ▀█▀▀█▄▄  
  █▄  ▀█▀█▄▄▀▀ ▀ ▄█▄▄█   
  ▀▀▀▀ ▀▀▀█ ▀█▄█▄▄▀█▄▄▄  
  █▀▀▀▀▀█ ▄ ▀▄█▄█▀ ▄█▀▄

> У кольоровому режимі кожен символ `▀` має колір верхньої половини як
> foreground, а нижньої — як background. Тому один рядок тексту кодує два
> рядки модулів, і код виходить удвічі «вищим» за символ.

## Як це працює

```
текст → біти → data codewords → ECC → інтерлівинг → матриця → маска → термінал / PNG
```

1. **Бітовий потік.** Режим `0100` (byte), 8-бітний лічильник довжини
   (16-бітний для v10+), самі байти, terminating zeros і пад-байти `0xEC`/`0x11`.
2. **Корекція помилок.** Для кожного блоку рахується залишок від ділення на
   генераторний многочлен Reed–Solomon у GF(256); дані й ECC чергуються
   між блоками згідно з таблицями версії/рівня.
3. **Матриця.** Спочатку малюються finder/timing/alignment-патерни, темний
   модуль і BCH-коди формату та версії. Потім дані вкладаються зигзагом у два
   правих стовпці, пропускаючи функціональні модулі.
4. **Маскування.** Пробуються всі 8 масок; для кожної рахується штраф
   (N1 — довгі серії, N2 — 2×2 однакового кольору, N3 — finder-подібні
   патерни, N4 — дисбаланс темних/світлих). Обирається найменший штраф.
5. **Вивід.** quiet zone 4 модулі; у терміналі — два модульні ряди на один
   текстовий рядок, у PNG — збільшені кольорові квадрати.

## Структура проєкту

```
qrterm/
├── main.go              # CLI, stdin, вивід у термінал, PNG
├── main_test.go         # тести CLI та рендеру
├── qr/
│   ├── qr.go            # публічний API: Encode(text, opts)
│   ├── tables.go        # таблиці версій/рівнів, alignment, capacities
│   ├── bits.go          # бітовий потік, падіння, інтерлівинг
│   ├── reed_solomon.go  # GF(256), генератор, залишок
│   ├── matrix.go        # функціональні патерни, format/version, data placement
│   ├── mask.go          # 8 масок і штрафні правила
│   └── qr_test.go       # тести енкодера
├── assets/preview.png
└── go.mod
```

## Перевірка

```bash
go test ./...
go vet ./...

# незалежне сканування згенерованого PNG
go run . -png /tmp/qr.png "hello world"
zbarimg -q --raw /tmp/qr.png

# звірка даних із еталонним енкодером
qrencode -t ASCII -m 0 -l M -o - "hello world"
```

Тести `TestDecodeWithZBar` і `TestMatchesQrencodeReference` автоматично
пропускаються, якщо `zbarimg` / `qrencode` не встановлені. Маска вибирається
евристично й може відрізнятися від інших енкодерів, тому еталон порівнюється
за **розмаскованим потоком даних**, а не за матрицею побітно.
